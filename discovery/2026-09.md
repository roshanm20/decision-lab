## 2026-09-23
- Statsig's guide to sample ratio mismatch (SRM) states the platform flags a test as mismatched when the chi-square p-value drops below 0.01. It does not explain why 0.01 rather than the usual 0.05. https://www.statsig.com/blog/sample-ratio-mismatch . BUILT, checked 2026-09-23, dated 2023 so not fresh, but the 0.01 default is what today's SRM checker uses, and the reasoning stated for it in the tool's own docs (this check runs on every experiment, so a 1-in-20 false alarm rate would flag good tests constantly) is the tool's own, not Statsig's.
- Microsoft's KDD 2019 paper on diagnosing SRM (Fabijan et al.) recommends an even stricter 0.0005 threshold, arguing real mismatches produce p-values far below any reasonable cutoff. https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/ . BUILT, checked 2026-09-23, the older of the two thresholds but the tool exposes both via --alpha and the docs page cites the reasoning.
- Optimizely's support page on its automatic SRM detection, updated 2026-03-06, describes checking for imbalance daily through the test rather than only at the end. https://support.optimizely.com/hc/en-us/articles/13409080412173-Optimizely-s-automatic-sample-ratio-mismatch-detection . QUEUED for a future marketing roadmap item: today's srm tool only checks one set of final counts, a day-by-day version that catches an SRM before the test ends rather than after would need a worked example of a daily count file first.
